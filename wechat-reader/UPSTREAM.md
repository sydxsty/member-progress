## Local image support (v13)

The reader identifies actual image bytes, supports legacy XOR and V1/V2 AES-ECB plus XOR, and validates real AES padding before accepting image keys. It reads existing memory in the selected Weixin process tree (including WeChatAppEx) using `PROCESS_VM_READ | PROCESS_QUERY_INFORMATION` only. No hook, injection, process restart, source write or upload occurs. The primary image-key path reads only `key_<code>_*.statistic` filenames in the current Windows user’s Tencent kvcomm directories. It derives the AES-128 key as the ASCII bytes of `md5(decimalCode + cleanedWxid).hexdigest()[:16]`, and binds XOR to `code & 255`. A candidate is accepted only after validation against that account’s actual image header and AES padding. Account image keys and their XOR values are kept in Windows current-user DPAPI only. Old and recent image samples are handled independently. Background sync uses local derivation and cached keys; only explicit `read --refresh-images` enables a bounded 45-second passive memory fallback for ASCII, UTF-16, binary and standard string candidates. A missing resident image key remains an explicit limitation and does not claim that a V2 image is inherently undecryptable.

Decoded files are written under the reader cache and keep stable attachment IDs, actual MIME, and the original encrypted path. Full-size/HD images precede thumbnails; a thumbnail fallback is marked. JPEG/PNG/GIF pixels are fully decoded before marking ready. WebP/BMP/TIFF are normalized to PNG. The upstream `wxgf` HEVC container decoder uses a pinned bundled FFmpeg to make standard JPEG/GIF output, usable by WebView2 and native Codex image input. FFmpeg is an LGPL build from BtbN (`ffmpeg-release.json` has exact version, source, download and SHA-256). `prepare-ffmpeg.ps1` verifies the archive and executable; `build.ps1` invokes it. Runtime reads need no download or installed converter.
